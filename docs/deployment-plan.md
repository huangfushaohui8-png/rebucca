# 东方宇阳 Rebucca 部署方案

版本：1.0.0｜日期：2026-10-04｜依据：固定上游 `8440b5545fc4f02bad105cbcc1ed09f24a0a2dfd` 与本次[安全审计](security-audit.md)。

**建议路径：先整改安全边界，再在主机 Docker 的隔离 Linux 环境做 1–2 路试验，验证后部署到现场 Linux 边缘服务器。当前原版不具备直接上线条件。** 本文件是部署与准入设计，不是已验证安装包；本期没有启动应用、下载 Docker 运行镜像、采购服务器或接入摄像头。

## 可用设备与选型

| 环境 | 本次实际核验 | 适合的下一步 |
| --- | --- | --- |
| 主机 Haoyus-MacBook-Pro.local | Intel i7，4 实核/8 线程，32GB；可用空间约 809GiB；Docker Server 29.7.2 可响应 | 隔离 Linux 容器、CPU 推理、合成/脱敏视频的功能试验 |
| 副机 huangfushaohuideMacBook-Pro.local | Intel x86_64，8 实核，32GB；可用空间约 341GiB；Docker 客户端存在，但 daemon socket 缺失 | 恢复 Docker 服务后可做另一环境复核；本期未启动其服务 |
| 现场生产候选 | 尚未提供或验收硬件与网络 | Linux x86_64 边缘服务器靠近摄像头，按实测容量选 CPU/GPU |

原版预置 Windows 与 Linux ZLM，无 macOS 原生运行文件。Mac 用 Linux 容器更合适；Intel Mac 的 Docker CPU 试验不能据此证明 NVIDIA CUDA、RK3588 或昇腾环境已支持。首期不采购设备，先测已有主机。

资源为试验起点，不是通过基准测得的路数承诺：

| 试验阶段 | 初始配置建议 | 判定方法 |
| --- | --- | --- |
| 1–2 路，CPU 小模型 | 主机给 Linux VM/容器约 4 核、8–12GB；640 输入，分析目标 2–5fps；先不用大模型和连续录像 | 实测解码、推理与队列延迟、内存、稳定性，逐路增加 |
| 4–8 路现场候选 | Linux 8 核、32GB；必要时 GPU 8–12GB 显存；独立存储 | 以相同模型、分辨率、码率、抽帧与报警场景压测，不能仅按显存推路数 |
| 8–16 路或复杂模型 | Linux 12–16 核、32–64GB；必要时 GPU 12–16GB；独立存储 | 本期未测，采购前用目标视频验证，容量不足时降分辨率/抽帧或分节点 |

`analysisTargetFps` 是分析目标抽帧频率，不意味着源视频只传输/解码这么多帧。并发路数取决于解码、模型、分辨率、场景和数据率。

## 部署关系

管理用户经 VPN 或内网 HTTPS 入口访问管理服务；摄像头处于设备 VLAN，通过批准的 RTSP/GB28181 与流媒体服务交互；小模型在低权限推理进程处理视频；SQLite 与业务文件落独立持久卷；可选大模型只处理获准外发的事件截图，首期默认关闭。

初期保留单机与 SQLite，避免尚无需要就引入集群和新数据库。真实并发和运维证据显示 SQLite 或单节点成为瓶颈时，再设计迁移与多节点状态协调。产品中的进程内单例、SQLite 锁和后台任务当前不能直接被多 WSGI worker 当作共享状态。

## 阶段 0：整改、可复现构建与网络隔离

1. 固定原始审计提交，建立唯一整改分支；按受影响模块补齐规格/任务/测试，保留原版最小复现。先修匿名 shell 执行与 `/inner/` 身份，随后角色、SQL、下载路径、静态业务文件和秘密泄露。
2. 用独立运行配置支持 `DEBUG=False`、受控 HOST、随机秘钥、强口令、HTTPS Cookie、CSRF；停用所有示例账户，去掉示例 LLM key。禁止把真实配置和数据库重新提交到公开 fork。
3. 移除默认版本遥测；版本信息用安全转义和 URL 白名单。取消运行时 torch.hub 下载；模型导入有来源、许可、SHA256、尺寸和低权限隔离。
4. 升级受支持 Django 5.2 LTS 的当前安全修订，以及其他命中公告的依赖；解析整个运行依赖图并锁版本/哈希，复测兼容性。减少运行镜像中的打包开发工具，扫描完整 Python 与系统依赖。
5. 从官方 ZLM 固定提交源码重建，核实 `-DDISABLE_REPORT=ON`，使用受维护的系统库；保留构建记录和映像摘要。需核对项目调用的 ZLM API、GB28181/RTP 模式和端口，不能直接声称最新版镜像完全兼容。
6. 核清播放器/字体/示例模型许可与来源；需要闭源商用时，不能认为把 YOLO 模型改成 ONNX 就消除了原许可义务。
7. 专用 Linux VM/容器低权限运行，限制内存/CPU/pids/磁盘，删除多余 capabilities，禁止 Docker socket、宿主 HOME/SSH/GitHub 凭据等挂载，启用 no-new-privileges。代码/模型尽量只读；数据库/录像/日志只挂需要的卷。
8. 离线或受限网段先验：默认拒绝出站；仅放行测试摄像头、批准的内部组件/DNS/时间服务。依赖安装在独立构建阶段；运行期不用公网下载代码或模型。Docker bridge 本身不等于出站防火墙，需实际配置并验收网络策略。

完成条件：修复负面回归通过，默认/匿名/普通用户越权受拒绝，凭据不出现在接口/日志/导出，模型/二进制来源和完整依赖风险有处置记录。

## 阶段 1：主机上的隔离试验

整改分支构建 Linux 镜像后，在主机 Docker 运行。首期先用合成或已脱敏本地视频，随后只接 1–2 路获准测试摄像头；不挂企业监控网、生产数据库或个人密钥。需要跨设备访问时使用 VPN/内网 HTTPS，禁止路由器端口映射直接公开。

上游真实演示命令为 `python manage.py runserver 0.0.0.0:10001`，它不是生产入口，也不是本次已验收命令。本阶段应在修复版的隔离网络、受控监听和独立流媒体进程下做试验。

重要启动兼容性：

- `GlobalUtils.py` 导入会启动 SIP；`InnerlView.py` 导入会启动代理初始化线程。常见管理命令也可能触发这些导入副作用，不能在宿主直接试跑。
- `AppConfig.ready()` 仅在 `RUN_MAIN=true` 时启动部分后台服务。改成 Gunicorn/其他 WSGI、使用 `--noreload` 或多 worker 时，这部分可能不启动；自动重载又可能重复初始化未被同样守护的其他模块。
- 因此生产整改要做明确的启动/停止生命周期，将流媒体/SIP/分析任务交给可管理进程；Web 初期只用一个 worker。不能仅把命令换成 Gunicorn 就宣称完成生产部署，也不能把设置 `RUN_MAIN` 当作长期解决办法。

本期没有提供伪称可用的 Dockerfile/Compose 或一键启动脚本；完成以上整改后再实现并从干净检出验证。

## 端口与配置

端口取自已核验 `config.json` 和 ZLM 配置；最终只有验收需要的端口才能开通。

| 端口/路径 | 用途 | 允许范围 |
| --- | --- | --- |
| HTTPS 443 | 管理与获授权的播放入口 | VPN/管理内网；生产 TLS |
| TCP 10001 | Django 管理后端 | 内部/本机，不能裸露公网；外部代理拒绝 `/inner/` |
| TCP 10002 | ZLM HTTP API、HTTP/WS 播放 | 内部 API 与受授权播放路由分开；代理禁止直通管理 API |
| TCP 10554 | ZLM RTSP | 指定内部分析/媒体端；鉴权或网络控制 |
| TCP 10935 | RTMP | 不使用则关闭；使用时仅批准推流端 |
| 15060，按设置的 UDP/TCP | SIP | 只允许设备 VLAN 的指定端点，配置唯一强凭据 |
| RTP 及相关端口 | GB28181 媒体 | 按实际 ZLM/RTP 分配模式定义范围后开通；首期 RTSP 不需要开放整片 UDP 范围 |
| `/inner/*` | 组件回调 | 独立服务身份+内网限制，不能依靠前端隐藏 |
| `/static/*` | 公共界面资源 | 不含录像、截图、模型、日志或导出文件 |

Linux 路径统一使用 `/` 与绝对路径；默认 `mediaStartPath` 是 Windows exe，必须映射到核验过的 Linux 程序。不要照抄 README 通过 HTTP 安装旧 `libssl1.1` 或宽泛 chmod 的建议；源码重建及受维护依赖是生产路线。

现有组件 API 优先使用本机或共享隔离网络。上游多处假定 `127.0.0.1`：若拆为多个容器，需要更改并测试 host 配置、回调、浏览器播放地址；不能直接把 localhost 当成另一容器。HTTPS 页面不能继续用裸 HTTP/WS 播放而造成混合内容，应通过受控 HTTPS/WSS 路由并验证流媒体代理。

## 持久化、容量与备份

| 数据 | 建议位置/处理 |
| --- | --- |
| SQLite | 独立可写持久卷；建立可重建 schema/版本迁移和唯一管理员初始化，不能直接发布示例数据库 |
| 模型 | 只读模型卷，来源/许可/摘要清单；导入操作单独受控 |
| 截图/报警证据/录像 | 非公开数据卷，按用户/摄像头授权读取；独立留存与磁盘配额 |
| 运行配置与秘密 | 不入 Git，不放公开 static，不在构建时写入镜像层；限制文件权限 |
| 日志 | 脱敏、轮转、限制总量与导出角色 |

原版没有完备的可追溯初始化/迁移交付；需要从审阅后的 schema 建立干净部署，而不是删除数据库后就假定 `migrate` 会建好所有业务表。

连续录像容量公式（十进制）：`每天每路 GB ≈ 码率 Mbps × 10.8`。例：4Mbps 约 43.2GB/路/天；8 路保留 7 天约 2.42TB，另留 20% 余量约 2.90TB。这是按稳定平均码率估算，不是实际录像测量，未包含模型、截图、备份等。不同编码和场景应测实际码率。主机首期关闭连续录像，只保存有限报警证据；生产录像用独立磁盘，避免耗尽系统盘。

备份先停止/暂停数据写入与分析，使用 SQLite backup API 或一致性备份，再复制配置、模型清单与业务文件；备份应加密并有恢复演练。不要只复制正在写入的 SQLite 文件就承诺一致性。

## 阶段 2：生产上线验收

| 项目 | 必须观察到的结果 | 当前状态 |
| --- | --- | --- |
| 认证/角色/回调 | 匿名、默认 token、低权限用户无法越权；业务文件受权限保护 | FAIL，待整改 |
| 命令/SQL/下载路径 | 恶意输入被拒绝且无额外执行、越界读取或删除 | FAIL，待整改 |
| 依赖/制品 | 完整锁文件和依赖扫描；二进制/镜像/模型/播放器可追溯 | PARTIAL |
| 外联/秘密 | 抓包只见批准端点；未授权域名访问被阻断，日志无敏感值 | NOT_RUN |
| 视频与报警 | 真实 RTSP/需要时 GB28181 接入、布控、报警截图和回溯闭环正常 | NOT_RUN |
| AI 质量 | 分开的开发/验收视频与人工标注；记录漏报、误报、时延及低光/遮挡条件 | NOT_RUN |
| 性能 | 指定硬件/模型/码率/路数下持续运行至少 24 小时，资源/队列不持续增长 | NOT_RUN |
| 故障/恢复 | 摄像头断流、模型不可用、磁盘不足、服务重启与备份恢复可观察处理 | NOT_RUN |
| 大模型 | 端点白名单、数据范围、费用上限与超时降级；未获准时不外发截图 | NOT_RUN |

误报/漏报与延迟阈值来自现场场景和处置成本，本期没有依据编造准确率或现场安全承诺。首期收集测试视频和独立标注，再确定可验收指标。AI 只产生事件候选与复核建议，现场人员核实处置；不把模型报警直接连接矿山设备控制。

## 版本发布与回退

每次发布登记源码 SHA、全部锁定依赖、构建环境、镜像摘要、模型摘要和许可、schema 版本及配置摘要；秘密本身不进发布表。先在同一制品上验收，再推广到现场。

回退先停止新任务，保存新生成数据与日志，切回上一个已验证不可变镜像/模型/配置；数据库 schema 的回退与镜像回退分别处理，必要时用已演练备份恢复。没有被验收的前一版本时，回退目标是停服隔离并保全数据，不是假装已有稳定版本。

## 执行清单

1. 以本次审计为基线建立整改分支和受影响模块任务，优先 F01/F02。
2. 修输入、权限、秘密、生产配置、依赖与外联，补负面回归与完整环境锁。
3. 生成可复现、低权限且没有默认公网访问的 Linux 构建；核清媒体/播放器/模型来源与许可。
4. 用主机 Docker 隔离环境完成合成视频和 1–2 路真实测试；产出 24 小时日志、容量和网络证据。
5. 根据证据选择现场 Linux 配置，完成恢复演练和 AI 质量验收后上线。

本期已完成源码取得、审计与方案；本清单中的产品整改、镜像构建、真实试验和生产部署均尚未执行。
